# Commerce Ops AI Agent Foundation 1.4.1

## Agent Monitoring Center

Status: implemented

Foundation 1.4.1 adds a read-only Agent monitoring surface to the active Vue
workbench. It consumes the authenticated Foundation 1.4 Observability API and
does not add a database migration, a business Agent, or a new execution path.

## User Goal

The monitoring center allows an operator or system administrator to answer:

- Is the Agent Runtime observable and how many runs are active?
- How many runs succeeded, failed, or remain in progress?
- How long do runs take and how many Tool calls or tokens do they consume?
- Which Agent or request failed?
- Which Context and Tool versions participated in one run?
- Has a deterministic, human, or model Evaluation been recorded?

## Frontend Architecture

| Layer | Implementation |
| --- | --- |
| Route | `/#/agent-monitoring` |
| Navigation | Governance group, `Agent 监控` |
| Page | `frontend/commerce-ops-vue/src/pages/AgentMonitoringPage.vue` |

| Tool chart | `frontend/commerce-ops-vue/src/components/AgentToolUsageChart.vue` |

The route is lazy-loaded. No additional package was introduced.

## Information Architecture

1. Runtime status and active-run count.
2. Date, Agent, status, and request-ID filters.
3. Run count, success rate, failures, duration, Tool calls, and token totals.
4. Run-volume/success-rate and Tool-usage charts.
5. Paginated run explorer.
6. Run detail drawer with Context versions, Tool trace, result digest, error
   code, and Evaluation results.

The page includes loading, error, empty, and retry states. Desktop and mobile
layouts use the existing workbench tokens and navigation behavior.

## API Contract

The page is read-only and calls only:

- `GET /api/ai/observability/status`
- `GET /api/ai/observability/summary`
- `GET /api/ai/observability/runs`
- `GET /api/ai/observability/runs/:runId`

It uses the same session authentication mechanism as the rest of the Vue
workbench. No write endpoint is exposed by the page.

## Privacy Boundary

The UI displays only the fields already projected by Foundation 1.4:

- identifiers and version references;
- counts, durations, token usage, and statuses;
- safe field-name lists, result sizes, and SHA-256 digests;
- bounded error codes and Evaluation reason codes.

Raw Prompt text, Context payloads, Tool payloads, Tool results, and business
output are not queried or rendered.

## Data And Migration Impact

- New tables: none.
- New migrations: none.
- Production database writes: none.
- Agent or Daily Report behavior changes: none.
- Existing storage: Foundation 1.4 `operation_audit_events` projection.

## Validation Contract

- Vue TypeScript check must pass.
- Vue workspace and Agent Observability focused tests must pass.
- Production build and Doctor must pass.
- Desktop width 1440 and mobile width 430 must have no page-level horizontal
  overflow.
- The browser console must have no warning or error generated by the page.
