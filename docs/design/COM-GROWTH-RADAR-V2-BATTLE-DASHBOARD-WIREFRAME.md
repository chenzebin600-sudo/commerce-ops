# COM-GROWTH-RADAR-V2 电商运营作战驾驶舱线框

> 线框版本：`GRV2-BATTLE-UI-1.0.0`
> 指标基线：`GRV2-METRICS-1.0.1`
> 日期：`2026-07-25`
> 状态：已确认产品方向，等待开发批准

## 1. 产品定位

Growth Radar V2 不是传统数据报表，而是面向同时负责大量店铺的电商运营人员的每日决策系统。

用户进入页面后，应在三分钟内回答四个问题：

1. 今天优先投入哪个国家、哪个类目？
2. 该方向优先处理哪些 SKU？
3. 哪些店铺和店长没有充分承接这些货盘？
4. 哪些现有优势款、缺货款或滞销款需要立即处理？

`GRV2-METRICS-1.0.1` 继续作为数据语义合同。此前 V2 页面和方向页保留为历史候选实现，但不再代表产品验收结果。本线框是新的页面验收基线。

## 2. 数据语义

### 2.1 货盘强度

货盘排名粒度：

```text
confirmed_country_code
+ category_level_1
+ category_level_2
+ normalized_source_sku
```

排名字段为马帮库存事实中的 `source_predicted_daily_sales`。

- 它表示来源预测日销量，不是公司真实销量。
- 同一 SKU 出现在多个仓库时，不累加预测日销量。
- 多仓非空预测值一致时采用该值；冲突时标记不可比较。
- 高表现 SKU 为同国家、同类目内达到 P80 的 SKU。

### 2.2 我方表现

我方销量只统计近 28 天状态为“已发货”的订单商品数量：

```text
own_daily_sales_28d
= own_shipped_quantity_28d / 28

own_capture_ratio_28d
= own_daily_sales_28d / source_predicted_daily_sales
```

页面必须称为“我方承接率”，不能称为市场份额。

近 28 天没有已发货订单只能解释为“近期未承接”，不能解释为“未上架”。

### 2.3 库存约束

```text
forecast_coverage_days
= available_quantity / source_predicted_daily_sales
```

可用库存和在途量分别展示。在途量不能计入当前可售库存。

## 3. 全局信息架构

左侧导航保持紧凑，一级入口固定为：

1. 驾驶舱
2. 货盘机会
3. 国家类目
4. 店铺分析
5. 蓝海机会
6. 重点 SKU
7. 报告中心

国家映射、店铺身份、店长归属和规则阈值从右上角“配置”入口进入。配置由用户在前端维护，版本化保存到数据库，不在代码中硬编码。

## 4. 驾驶舱首屏

桌面首屏采用 12 列紧凑网格，参考已确认截图的信息密度，但不复制演示数据。

### 4.1 顶部控制栏

固定展示：

- 数据日期
- 平台
- 国家
- 店铺
- 店长
- 最新成功分析标识
- 规则版本
- 发布状态
- 配置入口

筛选器联动所有卡片、图表和任务。筛选变化后保留在 URL 查询参数中。

### 4.2 核心指标条

五个指标按优先级展示：

| 指标 | 含义 | 点击后 |
|---|---|---|
| 高价值突破机会 | 高货盘强度、我方承接不足且库存可支撑 | 打开优先发力 SKU |
| 缺货风险 | 高需求且覆盖天数不超过 14 天 | 打开补货跟进 |
| 滞销库存 | 命中 60/90/180 天滞销规则 | 打开滞销清单 |
| 新品机会 | 90 天新品观察期内的有效机会 | 打开新品清单 |
| 重点跟进 SKU | 分配给当前范围的今日重点任务 | 打开任务队列 |

每个指标同时展示较昨日变化；没有可比快照时显示“暂无对比”，不能显示 0。

### 4.3 国家 x 类目机会地图

使用热力图展示国家与二级类目的机会强度。

每个单元格展示：

- 机会指数
- 国家内类目排名
- 高表现 SKU 数量
- 数据质量状态

机会指数是确定性排序指标：

```text
opportunity_index
= market_strength_percentile * 0.40
+ capture_gap_score * 0.30
+ stock_readiness_score * 0.20
+ opportunity_breadth_percentile * 0.10
```

其中：

- `market_strength_percentile`：国家类目来源预测日销量总量的分位。
- `capture_gap_score`：相对目标承接率的缺口；达到目标后为 0。
- `stock_readiness_score`：高表现 SKU 中覆盖天数不少于 14 天的比例。
- `opportunity_breadth_percentile`：高表现且可行动 SKU 数量的分位。

指数只用于排序，不代替证据。缺失国家映射、预测冲突或样本不足时单元格显示“不可比较”。

点击单元格下钻到对应国家和类目的 Top SKU。

### 4.4 验证货盘 Top SKU

按国家、类目内 `source_predicted_daily_sales DESC` 排序。

表格列：

- 排名
- SKU
- 国家
- 一级/二级类目
- 预测日销量
- 我方近 28 天已发货销量
- 我方承接率
- 可用库存 / 在途量 / 覆盖天数
- 方向标签
- 建议动作

方向标签固定为：

- `QUIET_ENTRY`：蓝海候选
- `PRIORITY_GROWTH`：优先发力
- `DEFEND_WINNER`：保持优势
- `SUPPLY_CONSTRAINED`：补货后发力

点击 SKU 打开证据抽屉，显示输入、公式、阈值、规则版本和数据时间。

### 4.5 货盘强度 vs 我方表现

使用四象限散点图：

- Y 轴：国家类目内货盘强度分位。
- X 轴：我方承接率。
- 点：SKU。
- 点大小：来源预测日销量。
- 点边框：库存状态。

默认分界：

- 高货盘强度：P80。
- 低承接：低于配置的承接率阈值，首版默认 10%。

四象限：

1. 已验证 + 我们弱：优先发力。
2. 已验证 + 我们强：持续经营。
3. 货盘较弱 + 我们强：观察优势。
4. 货盘较弱 + 我们弱：低优先。

点击点打开 SKU 证据抽屉。

### 4.6 蓝海机会池

蓝海候选必须同时满足：

```text
country_category_percentile >= P80
AND own_shipped_quantity_28d = 0
AND forecast_coverage_days >= 14
AND product_status is actionable
```

“0”必须来自完整订单范围内的真实聚合；订单范围不完整时不得进入蓝海池。

展示：

- SKU
- 国家
- 类目
- 预测日销量
- 可用库存
- 在途量
- 我方销量
- 证据状态
- 建议动作

### 4.7 今日运营指引

右侧任务队列是首屏的行动出口，不是普通告警列表。

每位店长每天最多生成 10 项任务，按以下顺序分配：

1. 我方现有亮点款的缺货风险。
2. 高价值国家类目中的承接缺口。
3. 蓝海候选 Top SKU。
4. 新品观察。
5. 滞销处理。

同一店长、国家、类目的相近 SKU 合并为一个任务，任务内列出 Top 5 SKU，避免为 50 家店铺生成数百条碎片告警。

任务状态：

- `NEW`
- `ACKNOWLEDGED`
- `DONE`
- `DISMISSED`

任务只提供建议，不自动执行上架、补货、广告或价格操作。

### 4.8 店铺 / 店长诊断

按店长聚合，并可展开店铺：

- 店长
- 店铺数
- 高表现货盘销售覆盖率
- 当前可售货盘销售覆盖率
- 今日机会数
- 异常数
- 重点方向

展开后显示：

- 该店铺已有亮点 SKU。
- 近期未充分承接的高表现 SKU。
- 库存可支撑的增长方向。
- 缺货和滞销异常。
- 证据与建议动作。

## 5. 分页页面

### 5.1 货盘机会

提供可筛选、可排序的全部方向清单，支持按方向、风险、国家、类目、店铺、店长和库存状态过滤。

### 5.2 国家类目

以热力图、排名条形图和趋势图解释国家类目变化。任何汇总都能下钻到 SKU。

### 5.3 店铺分析

先看店长，再看店铺，再看 SKU。默认按未处理高优先任务排序，不要求运营逐店巡检。

### 5.4 蓝海机会

聚焦近期未承接且库存可支撑的高表现 SKU，并明确显示“需核查上架和运营条件”。

### 5.5 重点 SKU

分为“本店亮点款”和“增长跟进款”，支持关注、备注、确认和完成任务。

## 6. 视觉与交互规范

- 整体为安静、紧凑、工作导向的 SaaS 后台。
- 页面标题使用紧凑字号，不使用营销式大标题。
- 卡片圆角不超过 8px，不嵌套卡片。
- 图表颜色同时配合标签、形状和图例，不只依赖颜色传达含义。
- 所有图表提供 tooltip、图例、空状态、加载状态、降级状态和数据时间。
- 表格超过 50 行时使用分页或虚拟化。
- 图标使用 Lucide，不使用手绘 SVG 或 emoji 作为功能图标。
- 任何“无数据”“不可比较”“配置缺失”都不能伪装成 0。

## 7. 响应式规则

### 桌面端

- 目标视口：1440 x 900。
- 首屏应同时看到筛选、KPI、机会地图、Top SKU、四象限、蓝海池、任务和店长诊断入口。
- 右侧任务队列可跨两行，但不得遮挡主内容。

### 430px 移动端

- 筛选器收进底部抽屉。
- KPI 使用两列网格，最后一项占满一行。
- 热力图和四象限切换为分段视图，不横向滚动整页。
- 宽表转换为重点字段列表，详情在抽屉中展开。
- 任务队列优先于低优先图表。

## 8. 验收标准

1. 运营人员可以从国家类目下钻到 SKU、店铺、店长和证据。
2. 页面明确区分预测日销量、我方实际销量和我方承接率。
3. 页面不出现“市场份额”“确定未上架”等超出证据的结论。
4. 每个机会和风险都给出明确原因与建议动作。
5. 20,000 SKU 规模下，首屏使用聚合结果，不在浏览器内全量计算。
6. 桌面和 430px 移动端无重叠、溢出或不可操作控件。
7. 新分析失败时继续展示上一份成功发布结果，并明确提示数据时间。
