# Growth Radar V2 运营方向合同

> 合同版本：`GRV2-METRICS-1.1.0`
> 日期：2026-07-25
> 状态：2026-07-27 已批准为 `1.0.1` 的正式后继合同；候选迁移尚未应用到正式数据库

## 1. 目标

Growth Radar 面向同时负责大量店铺的电商运营人员。页面不要求运营逐店、逐 SKU 排查，而是按以下顺序收敛问题：

```text
国家
-> 类目
-> SKU 预测日销量排名
-> 自营店铺已发货销量承接
-> 库存与在途约束
-> 明确运营方向
```

本版本不使用 AI 评分，不自动执行经营动作。每个方向必须保留输入、公式、规则版本和证据。

## 2. 核心粒度

### 2.1 货盘排名

排名粒度：

```text
confirmed_country_code
+ category_level_2
+ normalized_source_sku
```

二级类目缺失时才退回一级类目。禁止跨类目排名，也禁止在国家映射缺失时猜测国家。

排名指标使用马帮库存事实中的：

```text
source_predicted_daily_sales
```

同一 SKU 在多个仓库出现时，不累加预测日销量。只有所有非空值一致时才采用该值；存在冲突时标记 `SOURCE_PREDICTED_DAILY_SALES_CONFLICT`，不参与正式方向判断。

### 2.2 自营承接

自营销量只计算已确认店铺近 28 天的“已发货”订单商品数量。

```text
own_daily_sales_28d
= own_shipped_quantity_28d / 28

own_capture_ratio_28d
= own_daily_sales_28d / source_predicted_daily_sales
```

该比率表示自营对来源预测销量的承接程度，不是市场份额，也不能用于推断店铺是否已上架。

### 2.3 库存约束

```text
forecast_coverage_days
= available_quantity / source_predicted_daily_sales
```

可用库存和在途量分别展示。在途量不计入当前可售库存。

## 3. 方向规则

高预测 SKU 定义为同一国家、同一类目内达到 P80，且比较样本量达到配置下限。

| 方向 | 确定性条件 | 运营含义 |
|---|---|---|
| `QUIET_ENTRY` | 高预测、有可用库存或在途、自营近 28 天已发货数量为 0 | 悄悄入场 |
| `PRIORITY_GROWTH` | 高预测、自营承接率低于配置阈值 | 优先发力 |
| `DEFEND_WINNER` | 高预测、自营已有稳定承接 | 守住优势 |
| `SUPPLY_CONSTRAINED` | 高预测，但无可用库存或预测覆盖天数不超过 14 天 | 补货后发力 |

国家 SKU 和店铺 SKU 分别保存方向信号。缺失店铺映射、店长或国家配置时必须显示为“未配置/不可比较”，禁止格式化为零。

## 4. 配置边界

以下配置由用户在前端维护并版本化保存到数据库：

- 仓库到国家映射。
- 店铺身份、国家和店长。
- P80、最小样本量、低承接率和库存覆盖阈值。

国家映射不从仓库名或店铺名在正式分析中自动猜测。店铺未确认时不进入店铺和店长横向比较。

## 5. 可视化合同

方向总览必须包含：

- 国家与类目筛选。
- 国家 × 类目机会热力图。
- 悄悄入场、优先发力、补货后发力、守住优势的结构图。
- 高机会类目排行。
- 带预测排名、自营承接、库存、在途和覆盖天数的行动队列。

店铺横比必须包含：

- 店铺近 28 天已发货销量条形图。
- 店长待处理方向排行。
- 店长汇总表。
- 店铺销售覆盖和异常清单。

所有图表都必须能下钻到 SKU、店铺或证据详情，不能只展示没有行动含义的总数。

## 6. 数据不变量

1. `NULL` 不等于 0。
2. 预测日销量不等于自营实际销量。
3. 自营承接率不等于市场份额。
4. 历史未出单不等于未上架。
5. 多仓库存可以按规则聚合，预测日销量不能盲目跨仓累加。
6. 上一次成功发布结果在新分析失败时继续可读。
7. 合同批准不等于数据库部署批准；正式数据库在独立备份与发布确认前不得应用迁移 `019`、`020` 或 `021`。
