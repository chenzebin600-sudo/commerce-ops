# COM-GROWTH-RADAR-V2.2 马帮来源数据合同

> 合同编号：`GRV2-MABANG-SOURCE-1.0.0`
> 日期：2026-07-27
> 状态：已按业务负责人确认冻结
> 适用范围：Growth Radar V2.2 的马帮订单与库存来源事实
> 不代表：migration 批准、正式数据库写入批准或运营任务发布批准

## 1. 合同目的

本合同只回答一件事：

> 马帮导出的订单与库存字段分别代表什么，以及 Growth Radar 应如何读取这些来源事实。

本合同不定义最终机会阈值，不替代 Growth Radar 指标合同。凡与
`GRV2-METRICS-1.1.0` 冲突的内容，不回写旧版本，而由后继指标合同
`GRV2-METRICS-1.2.0` 显式承接。

## 2. 权威样本

本次字段确认基于以下人工导出文件：

- 用户提供的订单样例工作簿（`订单1.xlsx`）
- 用户提供的库存样例工作簿（`库存1.xlsx`）

它们代表未来马帮数据模块需要持续导入的数据结构。生产导入器必须保留同等字段语义，
不能因为数据库旧字段或旧测试假设而改变来源含义。

## 3. 订单来源合同

### 3.1 文件结构

订单文件包含订单头字段和商品明细字段。一个订单可以占多行：

- 第一行保存订单头和第一条商品明细。
- 后续商品行可以省略重复的订单头字段。
- 导入时只允许在同一订单范围内继承订单头字段。
- 商品数量、SKU、商品中文名称等商品字段必须按明细行读取。

订单事实的最小分析粒度为：

```text
order_id
+ order_line
+ normalized_sku
```

### 3.2 自营有效销量

Growth Radar 的我方订单销量使用商品明细行的商品数量，时间字段使用：

```text
付款时间
```

计入销量的订单状态固定为：

```text
已发货
待处理
配货中
已完成
```

其他状态不进入当前版本的我方销量：

```text
待审核
已作废
空状态
未知状态
```

计算公式：

```text
own_sales_quantity(window)
= SUM(order_line.product_quantity)
WHERE payment_time IN window
AND order_status IN ('已发货', '待处理', '配货中', '已完成')
```

不得使用订单头的 `SKU总数量` 替代明细数量。订单头数量与明细合计不一致时：

- 明细数量作为分析事实；
- 保存质量告警；
- 不删除来源订单。

### 3.3 店铺、平台、国家和负责人

订单字段语义：

| 字段 | 合同含义 |
|---|---|
| 店铺名 | 来源店铺身份 |
| 平台 | 来源平台 |
| 国家 | 订单经营国家，作为订单国家的首选事实 |
| 仓库 | 履约仓库，用于交叉校验和仓库分析 |
| 店长 | 当前实际负责人 |

负责人规则：

1. 首次导入时，来源 `店长` 作为店铺负责人的默认建议值。
2. 用户可以在前端人工修改负责人。
3. 人工修改后必须保存内部负责人标识、来源负责人、操作人、时间和修订版本。
4. 后续导入不得静默覆盖已确认的人工负责人。
5. 来源负责人发生变化时生成待确认差异，不自动改写。

国家规则：

- 订单分析优先使用订单文件中的显式 `国家`。
- 仓库到国家配置用于库存分析和订单交叉校验。
- 订单国家与仓库映射不一致时进入质量队列，不自动猜测或覆盖。

## 4. 库存来源合同

### 4.1 事实粒度

库存文件的最小事实粒度为：

```text
normalized_sku
+ source_warehouse
```

同一 SKU 可以出现在多个仓库。导入器必须保留每个仓库的独立事实，禁止在落库前按 SKU
覆盖或去重。

### 4.2 销量窗口

`销量(7/28/42)` 分别表示当前 `SKU + 仓库` 的近 7、28、42 天货盘总销量。

这些来源窗口采用与我方订单销量相同的有效状态范围：

```text
已发货
待处理
配货中
已完成
```

字段映射：

| 来源窗口 | 合同字段 |
|---|---|
| 近 7 天 | `source_sales_7d` |
| 近 28 天 | `source_sales_28d` |
| 近 42 天 | `source_sales_42d` |

这些值属于货盘来源销量，不是单个店铺销量，也不是平台市场总销量。

国家 + SKU 聚合时：

```text
source_sales_Nd(country, sku)
= SUM(source_sales_Nd)
  over unique warehouses mapped to the country
```

必须先按 `SKU + 仓库` 去重，再按已确认国家映射求和。禁止跨国家求和后再用于国家排名。

### 4.3 预测日销量

`预测日销量(个)` 是马帮在某一国家、某一仓库范围内给出的公司销量总和预测，
来源记录粒度仍为 `SKU + 仓库`。

合同字段：

```text
source_predicted_daily_sales
```

国家 + SKU 聚合时：

```text
source_predicted_daily_sales(country, sku)
= SUM(source_predicted_daily_sales)
  over unique warehouses mapped to the country
```

该字段用于同一国家、同一类目内的 SKU 排名和货盘机会分析。页面文案必须使用
“货盘预测日销量”或“来源预测日销量”，不得称为市场销量、市场份额或单店实际销量。

### 4.4 库存字段

| 来源字段 | 合同规则 |
|---|---|
| 可用库存量 | 可按已确认国家内唯一仓库求和 |
| 在途量 | 与可用库存分开展示，可按已确认国家内唯一仓库求和 |
| 当前可售天数 | 直接使用马帮结果，不自行重算 |

`当前可售天数` 不允许跨仓求和或平均。国家 + SKU 页面应保留仓库明细，并可展示
最小值到最大值。若后续风险规则要使用单一国家值，必须在后继指标合同中单独批准，
不能在本合同中隐式选择 `min`、`max` 或加权值。

### 4.5 活跃度

马帮已经计算：

```text
爆款
旺款
平款
滞销款
```

第一版直接使用该来源分类，不重新计算，也不把空值推断为某一分类。

合同字段建议：

```text
source_activity_label
source_activity_status = provided | unavailable
```

后续如改用 Commerce Ops 自有指标，必须使用新的规则版本，并保留原始马帮分类作为证据。

### 4.6 新品

第一版新品依据为：

```text
是否新款 = 是
```

合同字段建议：

```text
source_is_new = true | false
```

该来源标记可以直接产生“来源新品”候选，不依赖产品中心生命周期映射。产品中心动作仍需
精确 SKU 映射，不能因为来源新品标记而自动创建或修改产品。

## 5. 国家与仓库配置

库存国家维度必须来自用户维护的仓库到国家配置：

```text
source_warehouse -> controlled_country_code
```

规则：

1. 配置在前端维护并保存到数据库。
2. 正式分析只使用已激活版本。
3. 未映射仓库不得参与国家级结论。
4. 系统可以根据仓库名称给出候选，但必须由用户确认。
5. 来源文件中的正常中文仓库名必须原样保存。
6. 数据库中的乱码仓库别名视为导入编码缺陷，不能当作来源新仓库。

## 6. 来源样本质量基线

### 6.1 订单文件

- 57,915 条数据行。
- 33,542 个唯一订单头。
- 57,912 条带 SKU 的商品明细。
- 131 家店铺、21 名来源店长。
- 每家店铺在样本中只对应一个店长、一个国家和一个平台。
- 付款时间覆盖 2026-07-12 至 2026-07-26，共 15 个连续日期。
- 19 个订单头的 `SKU总数量` 与商品明细数量合计不一致。
- 13 个订单 SKU 未在库存样本中出现。

### 6.2 库存文件

- 20,046 条 `SKU + 仓库` 事实。
- 10,335 个唯一 SKU。
- 24 个正常仓库，样本中不存在重复 `SKU + 仓库` 键。
- 260 条来源新款记录，对应 196 个唯一 SKU。
- `活跃度` 有 3,725 条空值，必须保留为不可用。
- 3,678 个 SKU 在不同仓库的预测日销量不同；按本合同这是仓库级事实，不是冲突。
- 768 个 `SKU + 国家` 在同一国家的不同仓库值不同；按国家分析时依合同求和。
- 当前可售天数只有约 63% 等于简单的“可用库存 ÷ 预测日销量”取整结果，
  因此必须直接使用来源值。

## 7. 导入质量门禁

正式分析前必须满足：

1. 订单多行结构正确继承，不能生成孤立商品行。
2. 商品数量使用明细行，订单头差异有质量记录。
3. 订单有效状态严格使用本合同的四个状态。
4. 销量时间严格使用付款时间。
5. 库存不存在重复 `SKU + 仓库` 键。
6. 24 个来源仓库全部获得配置结果，或被用户明确排除。
7. 乱码只作为导入质量问题处理，不污染国家配置。
8. 空 SKU、空仓库、未知状态和异常数量 fail-closed。
9. 个人信息字段不得进入 Growth Radar 指标证据或前端响应。
10. 每次分析记录订单批次、库存批次、国家映射版本和规则版本。

## 8. 对既有指标合同的影响

以下 `GRV2-METRICS-1.1.0` 规则已被本来源合同证明需要后继版本：

| 旧规则 | 新确认事实 |
|---|---|
| 我方销量只计“已发货” | 计入已发货、待处理、配货中、已完成 |
| 多仓预测日销量不累加 | 在已确认国家内按唯一仓库求和 |
| 可售天数自行重算 | 直接使用马帮当前可售天数 |
| 新品依赖产品中心生命周期 | 第一版以来源 `是否新款=是` 为依据 |
| 店长需要另行全量填写 | 来源店长为当前实际负责人，允许人工覆盖 |

处理原则：

- `GRV2-METRICS-1.1.0` 保留为历史合同。
- 新增 `GRV2-METRICS-1.2.0` 后继合同后，分析器才能采用这些变化。
- 在 `1.2.0` 批准前，不修改正式分析规则、不应用 migration、不发布运营任务。

## 9. 非目标

本合同不批准：

- 修改正式数据库；
- 创建或应用 migration；
- 修改 A2；
- 修改 COM-015；
- AI 评分；
- 自动执行运营动作；
- 将来源预测日销量称为市场真实销量；
- 将历史未出单解释为未上架。
