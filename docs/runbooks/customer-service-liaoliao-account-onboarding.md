# 乐聊账号接入与本机监控操作手册

版本：1.0  
日期：2026-08-08  
适用范围：Commerce Ops 客服中心第一阶段

## 你需要操作的内容

1. 打开 `http://127.0.0.1:3101/vue-preview/#/customer-service`。
2. 点击“接入乐聊账号”。
3. 只填写账号显示名称和业务国家；不要在 Commerce Ops 中填写乐聊密码、Cookie、验证码或 Session。
4. 点击“打开乐聊登录窗口”。系统会启动一个独立、可见的 Chromium 窗口。
5. 在该窗口内人工完成乐聊登录、扫码、验证码或二次验证。
6. 保持窗口开启。系统检测到登录成功后会在本机原子保存 Session，并自动切换到持续监控；不需要回到弹窗再次确认。
7. 客服中心显示“监控运行中”后，该账号才算接入完成。

接入账号固定从 `OBSERVE_ONLY` 开始。此阶段只读取页面上已登录账号可见的会话、消息和右侧面板，不生成发送动作。

## AI 建议与输入框回填

接入账号不等于立即开启 AI。系统按以下顺序逐级放行：

1. `OBSERVE_ONLY`：采集消息和上下文，不调用回复模型。
2. `SUGGEST_ONLY`：具备已发布的 SUPPORT 产品知识版本、已配置 Reply Agent、至少一条已观察入站消息并开启全局 AI 后，才生成回复建议。
3. `DRAFT_FILL`：至少一条建议已经人工接受或编辑，并同时开启全局回填和账号回填后，才允许把低风险建议填入对应乐聊输入框。

无论处于哪个阶段，系统都没有自动发送能力，不会点击“发送”，也不会通过 Enter 键发送。客服必须在乐聊中检查草稿后亲自发送。

## 多账号规则

- 登录窗口一次只打开一个，避免扫码、验证码和 Session 归属混淆；第一个账号进入监控后再接入下一个。
- 每个账号使用独立的浏览器 Session、SQLite、日志和中央 Worker 身份，不能共用目录。
- 单机默认同时运行 4 个监控，硬上限 12 个；超过默认并发时应按客服电脑拆分，不要直接把 300 个账号堆在一台机器上。
- 同一乐聊账号只能有一个主 Worker；重复启动会在打开浏览器前被中央租约拒绝。

## 常见状态

- “等待人工登录”：请在独立 Chromium 中继续完成验证。
- “本机 Session 已保存”：登录已成功，系统正在切换到监控。
- “监控运行中”：账号已接入并持续采集。
- “需要重新登录”：Session 已失效，点击重试并重新完成人工登录。
- “本机运行环境不可用”：检查 Python 虚拟环境、Playwright Chromium 和项目路径，不要通过上传 Cookie 绕过。

## 安全边界

- 乐聊密码、Cookie、验证码和浏览器存储状态只存在于登录窗口或本机 Session 目录，不进入中央 PostgreSQL。
- 内部 Worker Token 由主系统自动生成并保存在本机受控文件中，页面和接口不会返回其明文。
- 关闭或停止监控不会发送任何客户消息；删除账号或 Session 属于另一个受控操作，不由“停止监控”隐式执行。
