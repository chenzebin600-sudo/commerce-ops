# 数据仓库动态文档设计

## 目标

交付一个独立于现有 `znwx-ai` 系统的 Windows 本地工具。用户双击批处理文件后，浏览器自动打开交互式文档，可以使用已有的 `zndr_` 数据 Key 检查权限、查询数仓并导出结果。

工具不修改现有系统菜单、服务、配置或业务代码，也不要求额外安装 npm 依赖。

## 交付位置

工具放在独立目录：

```text
deliverables/data-warehouse-dynamic-doc/
```

计划包含：

```text
启动数据仓库文档.bat
server.mjs
public/
  index.html
  app.css
  app.js
README.md
```

## 运行方式

`启动数据仓库文档.bat` 检查 Node.js 是否可用，启动本地服务，并在默认浏览器中打开工具页面。批处理窗口在工具运行期间保持打开，并明确提示“关闭此窗口即可停止工具”。服务只监听 `127.0.0.1`，不允许局域网其他设备访问。

本地页面调用同源的本地代理端点。本地服务再将请求转发到：

```text
http://10.110.80.95:8788
```

这样避免浏览器直接访问内网 API 时遇到跨域限制。

## 安全边界

- Key 由用户在页面中输入。
- Key 只保存在当前页面的 JavaScript 内存中。
- 不写入文件、Cookie、localStorage、sessionStorage 或 URL。
- 本地代理不会记录请求头、请求体或 Key。
- 浏览器关闭或页面刷新后需要重新输入 Key。
- 代理仅允许访问固定的 `/api/data/me`、`/api/data/catalog` 和 `/api/data/query`。
- 代理拒绝任意目标 URL、任意路径和非预期 HTTP 方法，避免成为通用转发器。
- 响应添加禁止缓存头，降低含权限信息和查询结果被缓存的风险。

## 页面结构

页面采用浅色、紧凑、可信的内部工具风格。桌面端为左右布局，窄屏自动变为单列。

### 连接区

- 数据 Key 输入框
- 显示或隐藏 Key
- “验证并读取权限”按钮
- 当前连接状态
- 角色、店铺数、权限范围版本和已开放产品摘要

只有验证成功后，查询区才可操作。

### 查询区

产品选择支持：

- 日销
- 库存
- 产品包
- 控价

切换产品时动态显示对应参数：

- 日销：开始、结束、店编、国家、大品类
- 库存：国家、大品类、SKU、款号、只看有货
- 产品包：国家、大品类、SKU、款号
- 控价：平台、国家、大品类、SKU

页面大小默认 500，允许范围为 1-2000。表单只发送有值的可选参数。

`/api/data/catalog` 返回的信息用于显示当前用户可用的产品、参数和字段。若目录信息和内置表单定义不一致，页面禁用有冲突的查询并提示用户查看最新接口文档。

### 结果区

- 显示产品、角色、行数、耗时、水位和范围版本
- 根据返回记录自动生成列
- 表头固定，表格支持横向滚动
- 空结果显示明确提示
- `还有更多=true` 时显示“加载下一页”
- 下一页使用服务端返回的游标，不自行解析或修改
- 新查询会清空旧游标和旧结果
- 支持将当前已加载的全部行导出为 UTF-8 BOM CSV，保证中文在 Excel 中正常显示

## 数据流

1. 用户输入 Key 并点击验证。
2. 页面把 Key 放在请求头中调用本地 `/proxy/me`。
3. 本地服务转发到数仓 `/api/data/me`。
4. 验证成功后，页面调用 `/proxy/catalog` 获取可用产品和字段。
5. 用户填写条件并提交查询。
6. 页面调用本地 `/proxy/query`，本地服务原样转发受支持的查询结构。
7. 页面展示响应元数据和结果行。
8. 如有更多数据，页面把上一页游标原样带入下一次请求。

## 输入约束

- Key 必须为非空字符串，并提示用户确认是 `zndr_` 数据 Key。
- 请求产品只能是日销、库存、产品包或控价。
- 顶层请求只构造 `产品`、`参数`、`页大小`、`游标`。
- 日销开始和结束必须填写，并在浏览器端检查日期顺序及最长 92 天。
- 国家只允许 `TH`、`PH`、`ID`、`MY`、`VN`、`SG`、`TW`。
- 控价平台只允许 `SHOPEE`、`SHOPEE_MALL`、`LAZADA`、`LAZADA_MALL`、`TIKTOK`。
- 页大小必须为 1-2000 的整数。
- 浏览器端校验用于改善体验，服务端响应仍为最终判断依据。

## 错误处理

- 无法连接：提示确认公司局域网连接和数仓服务状态。
- 400：展示接口返回的参数错误，并保留当前表单。
- 403：提示 Key 无效、已重新签发、被停用、产品未开通或查询越界。
- 429：提示查询队列已满，建议稍后重试。
- 502：展示经过纯文本处理的数仓错误信息，不渲染服务端 HTML。
- 本地端口占用：启动脚本自动尝试一个小范围内的后续端口，并把最终地址传给浏览器。
- Node.js 不可用：批处理窗口给出清晰中文说明并暂停，避免一闪而过。

## 可访问性与交互

- 所有输入框有可见标签，不用占位符代替标签。
- 键盘可完成全部操作，焦点状态清晰。
- 状态不只通过颜色表达，同时提供文字和图标。
- 按钮在请求进行期间禁用，防止重复提交。
- 表格数字保持原始精度，不在展示层擅自改写。
- 动效仅用于加载和状态切换，并尊重 `prefers-reduced-motion`。

## 技术实现

- Node.js 原生 `http`、`fs`、`path` 和 `child_process` 模块。
- 前端使用原生 HTML、CSS 和 JavaScript。
- 不引入第三方运行时依赖，不使用 CDN。
- 服务启动后自动打开系统默认浏览器。
- 服务进程退出后不留下后台守护进程。

## 测试与验收

### 自动检查

- 本地服务只绑定 `127.0.0.1`。
- 静态文件可以正常加载。
- 代理拒绝未知路径和不支持的方法。
- 代理不会在响应或日志中回显 Key。
- 查询请求只允许预期顶层字段。
- CSV 正确转义逗号、双引号、换行和空值。
- 日销日期窗口校验覆盖 92 天边界。

### 手工验收

- 双击批处理后能自动打开页面。
- 输入有效 Key 后能看到本人权限范围。
- 四个产品显示正确的动态表单。
- 至少完成一次实际查询并显示结果。
- 有更多数据时可以加载下一页。
- 导出的 CSV 可由 Excel 正确打开并显示中文。
- 刷新页面后 Key 已被清除。
- 关闭批处理窗口后，本地服务退出且端口不再监听。

## 不在本次范围

- 不保存或自动填写 Key。
- 不提供数据库账号或直接 SQL 功能。
- 不增加定时任务、后台同步或自动重试队列。
- 不接入现有 `znwx-ai` 页面、路由、菜单、数据库或权限系统。
- 不打包为 EXE 或安装程序。
- 不提供多人共享部署。
