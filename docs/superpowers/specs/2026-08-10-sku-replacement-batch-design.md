# SKU 替换分类筛选与批量执行设计

## 背景

缺货处理工作台的第二步当前以商品行为单位展示 SKU 候选。用户选择候选后，需要在单个商品行上立即确认并执行。候选数量较多时，这种方式难以筛选，也无法先完成整批选择再统一提交。

本次改造目标是：让用户先按替换类型、风险和处理状态筛选候选，为多个缺货商品行各选定一个候选，最后一次确认并创建可恢复的后台批量任务。批次内单项失败不阻断后续项目。

## 范围

### 包含

- 按替换类型筛选：全部、完全同款、同款换色、更小规格、更小规格加换色。
- 按风险等级筛选：全部、低、中、高。
- 按处理状态筛选：全部、未选择、已选择、无候选、执行中、已完成、失败、需人工核对。
- 每个缺货商品行最多选择一个替换 SKU。
- 候选卡片点击仅更新选择状态，不调用马帮写接口。
- 对全部已选商品行进行一次批量确认。
- 后台串行执行、逐项持久化进度、响应中断后恢复。
- 单项失败后继续执行其余项目，并显示逐项结果。

### 不包含

- 按店铺筛选。
- 按仓库筛选。
- 并行修改多个商品行。
- 自动选择候选 SKU。
- 修改平台买家订单商品；本功能仍只修改马帮履约 SKU。
- 对失败项目自动重试。

## 交互设计

### 筛选栏

SKU 替换建议标题下方增加紧凑筛选栏。替换类型使用分段按钮或标签组，风险等级与处理状态使用选择器。筛选只影响列表可见范围，不改变或清除已选择项目。

筛选栏同时显示“当前显示 X 个缺货商品 / 共 Y 个”和“已选择 N 项”。没有匹配结果时显示带恢复动作的空状态，用户可以一键清除筛选。

### 候选选择

候选卡片是单选行为：

- 点击未选卡片，将其设为该商品行的选中候选。
- 点击同一张已选卡片，取消该商品行选择。
- 点击同商品行的另一张卡片，切换选择。
- 组合或分包商品继续禁止自动选择和批量执行。
- 已选卡片显示明确文字“已加入批量替换”，并保留 `aria-pressed` 状态。

选择操作不创建后端计划、不读取马帮详情、不执行写入。

### 批量操作栏

SKU 建议面板底部增加批量操作栏，显示：

- 已选择商品项数。
- 涉及订单数。
- 清空选择。
- 批量替换所选 SKU。

没有选择时，批量按钮禁用并显示操作提示。执行期间禁止修改选择。

点击批量按钮后，前端把全部选择提交给批量计划接口。服务端重新读取订单与库存，并为每项生成不可变计划。计划完成后弹出一次确认框，展示可执行项数、预验证失败项数和风险分布。用户必须输入：

`确认批量更换SKU N项`

其中 N 是服务端重新验证后可执行的商品项数。确认前不得调用任何马帮写接口。

## 后端设计

### 批量计划

新增批量计划接口，输入为选择数组：订单号、商品行 ID、目标 SKU。服务端执行以下工作：

1. 校验数量上限、重复项和字段格式；每批最多选择 100 个商品行。
2. 同一订单内按商品行去重，每个商品行只能有一个目标 SKU。
3. 为每项执行现有单项计划的全部安全检查：账号权限、物流状态、原 SKU、数量、仓库、库存、候选规则和马帮库存标识。
4. 将可执行计划与预验证失败项写入批量计划文件。
5. 返回批次哈希、过期时间、确认文字和汇总信息。

批量计划是一次性、限时且不可篡改的。确认文字中的数量以服务端可执行项为准。

### 后台批次任务

批量执行接口验证批次哈希和确认文字后，创建持久化任务并立即返回任务 ID。任务按输入顺序串行执行：

1. 每项执行前重新检查库存、订单状态和计划一致性。
2. 调用马帮 SKU 更换。
3. 回读订单确认目标 SKU 已写入。
4. 将该项结果原子写入任务记录。
5. 无论该项成功或失败，都继续下一项。

同一个任务不得重复启动。同一商品行的计划不得执行两次。任务进入执行后，新版本部署或安全重启必须等待当前写操作完成。

### 状态与恢复

新增任务查询接口，返回：

- `QUEUED`、`RUNNING`、`COMPLETED` 或 `COMPLETED_WITH_FAILURES`。
- 总项数、已处理、成功、失败、当前项。
- 每项的订单号、原 SKU、目标 SKU、状态、错误码和错误信息。

前端拿到任务 ID 后轮询状态。页面刷新或连接中断后，可通过任务 ID 恢复；最近批次任务 ID 同时保存在当前页面会话中。服务端记录是最终事实来源。

任务进程意外退出时，不自动重放状态不确定的写操作。已明确成功的项目保持成功；正在执行但未完成回读的项目标记为“需人工核对”，其余尚未开始项目可由用户重新创建批次。

## 错误处理

- 预验证失败：不进入执行队列，在确认框和最终结果中说明原因。
- 执行前状态变化：当前项失败，继续下一项。
- 马帮拒绝写入：当前项失败，保留原始错误码与精简信息。
- 写入后回读不一致：标记“需人工核对”，禁止自动重试。
- 前端请求中断：后台任务继续，页面通过任务 ID 恢复。
- 3112 进入排空模式：拒绝创建新批次，已运行批次完成后再退出。

## 前端状态模型

选择状态使用 `订单号 + 商品行 ID -> 目标 SKU` 的映射。筛选状态与选择状态分离，因此切换筛选不会丢失选择。

批量任务有以下 UI 阶段：

1. `SELECTING`：允许筛选和选择。
2. `PLANNING`：服务端重新验证，选择冻结。
3. `AWAITING_CONFIRMATION`：显示汇总并等待确认。
4. `EXECUTING`：显示批次进度，禁止修改选择。
5. `FINISHED`：显示逐项结果，可按处理状态筛选，包括需要人工核对的状态不确定项目。

## API 轮廓

- `POST /api/fulfillment/sku-replacements/batch-plan`
- `POST /api/fulfillment/sku-replacements/batch-execute`
- `GET /api/fulfillment/sku-replacements/batch-executions/:taskId`

3101 代理层为相同路径提供输入校验、演员身份断言和超时控制。批量执行创建任务后立即响应，不保持长连接。

## 测试策略

### 服务层

- 批量计划拒绝同一商品行的多个目标 SKU。
- 批量计划保留有效项并记录预验证失败项。
- 确认文字必须精确匹配服务端可执行数量。
- 批量执行严格串行。
- 单项失败后继续执行后续项目。
- 每项完成后持久化进度。
- 同一任务无法重复启动。
- 状态不确定的项目不会自动重试。

### 代理层

- 新路径正确转发并限制请求体。
- 写接口需要可信操作人断言。
- 非法任务 ID 与超量选择返回明确错误。

### 前端

- 类型、风险和状态筛选组合正确。
- 筛选变化不清除选择。
- 同商品行只能选择一个候选，再次点击可取消。
- 点击候选不会调用计划或执行接口。
- 批量按钮只在至少选择一项时可用。
- 批量确认数量使用服务端计划结果。
- 轮询结果正确更新成功、失败和需人工核对状态。

## 验收标准

- 用户能在 115 个候选中按指定三类条件组合筛选。
- 用户能为多个缺货商品行先完成选择，再进行一次批量确认。
- 选择候选卡片时不会产生任何马帮写操作。
- 单项失败不阻断后续项目。
- 页面刷新或短暂断线后可恢复批次状态。
- 最终结果逐项可追踪，并能按处理状态筛选。
