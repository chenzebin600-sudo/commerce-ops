# Shopee 折扣控价三步式操作流设计

## 目标

把当前平铺的折扣控价页面改为明确的三步操作流，让运营随时知道当前步骤、下一步动作以及为什么不能继续。此次只调整前端信息架构与交互，不改变既有价格计算、人工确认、执行门禁、异常协调和后端接口语义。

## 方案选择

采用“单页引导式三步流程”：顶部持续显示步骤进度，正文突出当前步骤，但允许返回已完成步骤修改。相比只增加编号标题，它能明显降低页面拥挤；相比完全分页向导，它保留运营核对范围、覆盖规则和预览结果的上下文。

## 页面结构

### 第一步：选择任务与范围

本步集中展示创建方案所需的基础字段：

- 国家、店铺范围和大品类。
- 工作流。面向运营显示为“新建或续期折扣活动”和“修正现有折扣活动”，内部继续使用既有枚举值。
- 默认价格档位和续期开始时间等与所选工作流有关的字段。
- 当前模块状态采用紧凑提示呈现；安全设置移入“系统设置”折叠区，不再与日常操作争夺视觉焦点。

主按钮为“下一步：配置例外”。缺少必填项时按钮禁用，并在字段附近显示具体原因。

### 第二步：配置例外并生成预览

默认规则首先以摘要形式展示，例如“覆盖所选店铺全部在售商品，使用日常价”。运营不需要设置例外时可以直接生成预览。

店铺覆盖、链接覆盖、当前 Discount 活动和 CSV 批量导入统一放入“例外与高级设置”区域：

- 默认折叠，显示已配置数量。
- 选择“修正现有折扣活动”时，当前活动选择自动展开并标注为必要配置。
- 链接和批量导入继续保留备注、服务端校验与回显。
- 修改任何会影响方案的字段时，现有预览、确认信息和执行资格继续按原规则失效。

本步唯一主按钮为“生成价格预览”。请求期间显示明确加载状态；失败时在按钮上方展示可操作的原因，而不是只有短暂 toast。

### 第三步：人工确认并执行

预览成功后自动进入第三步并滚动到结果摘要。内容顺序为：

1. 方案摘要：店铺、商品、可执行、跳过和异常数量。
2. 价格明细：保留现有分页表格和状态解释。
3. 人工确认：运营姓名、精确确认语句和方案根摘要。
4. 执行动作：批准后才显示或启用执行按钮；所有写入门禁继续生效。

当预览需要重新生成时，第三步显示“返回第二步修改”而不是保留可执行错觉。执行中的方案继续提供恢复或重新检查入口。

## 辅助信息区

执行进度、UNKNOWN 协调和续期提醒不属于首次创建方案的三步主路径，移动到主流程下方的“运行与异常”区域：

- 默认展示当前方案执行状态。
- 历史执行、UNKNOWN、续期提醒使用二级标签切换。
- 未选择或恢复方案时显示明确空状态和操作入口。

## 状态与导航

- 步骤一完成基础校验后才能进入步骤二。
- 预览请求开始即锁定步骤一、二对应输入，避免请求期间继续修改造成旧结果回写。
- 预览成功后进入步骤三；预览失败停留在步骤二。
- 返回步骤一或修改方案字段会废弃旧预览及人工确认，沿用现有请求 generation guard。
- 页面刷新后若恢复到正在执行的方案，步骤直接定位到第三步。
- 步骤条可点击已完成步骤，不允许跳到尚未满足条件的步骤。

## 响应式与可访问性

- 桌面端步骤条横向排列，移动端改为紧凑纵向或编号导航。
- 每一步使用语义化 `section` 和清晰标题；步骤变化后更新焦点或滚动位置。
- 每一步只保留一个视觉主按钮，其余动作使用次级或文本按钮。
- 禁用按钮附近必须说明原因；键盘焦点、加载态、错误态和空状态继续可见。

## 测试范围

- 前端流程控制测试：步骤推进、返回修改、预览成功/失败、旧响应失效、恢复执行方案。
- 页面契约测试：三步标题、工作流文案、主按钮唯一性、高级设置折叠、禁用原因。
- 现有 typed client、API、价格预览和执行测试必须保持通过。
- Vue 类型检查和生产构建必须通过，并在桌面及移动宽度做视觉检查。

## 非目标

- 不改变数仓字段、SKU 匹配、价格取整或 1% off 规则。
- 不改变 Shopee 读写适配器、人工确认语义和写入安全门禁。
- 不新增自动审批、自动执行或新的后端工作流。
