# 马帮 SKU 更换单笔诊断设计

## 目标

在不依赖马帮网页按钮的情况下，通过后端内部接口安全测试一笔订单的履约 SKU 更换，并保留足够的马帮响应信息用于判断失败原因。

测试订单固定为 `20213797082782605624288044`，商品行 `477372993`，从 `T5AA3413198` 更换为 `T3AA1673198`。两者中文名、颜色和规格相同。本次不得操作其他订单。

## 方案

继续使用现有 `doChanegOrderItem` 内部接口，但将写入边界封装为可测试的结果解析流程。接口响应只能保留经过裁剪和脱敏的诊断字段，例如 HTTP 状态、`success`、业务错误码以及短错误消息；不得记录 Cookie、请求头、账号、密码或完整 HTML。

无论接口返回是否符合旧版 `success=true/1`，系统都必须在同一次执行中进行一次订单回读。实际回读到的 SKU 是最终事实来源：

- 回读为 `T3AA1673198`：判定成功。
- 回读仍为 `T5AA3413198`：判定马帮拒绝，返回经过脱敏的业务错误。
- 接口超时、连接中断或无法确认回读结果：标记人工核对，不得自动重试。
- 回读为其他 SKU 或商品行消失：标记人工核对，不得继续操作。

## 代码边界

- `scripts/mabang_order_source.py` 负责 HTTP 调用、响应规范化和写后回读。
- `scripts/mabang_worker.py` 保持明确的真实写入确认标记，不新增绕过入口。
- 履约服务继续串行执行并持久化结果；此次只通过单项执行入口测试，不启动四单批量任务。
- 响应规范化逻辑应为独立纯函数，使测试无需连接马帮即可覆盖返回格式差异。

## 测试策略

先写失败测试，再写实现：

1. 马帮返回 `success=true` 时，规范化结果表示已确认。
2. 马帮返回 `success=false` 和业务消息时，规范化结果保留裁剪后的错误码与消息。
3. 马帮返回其他成功形态时，不因旧版窄判断直接丢失信息。
4. 写入响应未确认但回读已是目标 SKU 时，最终判定成功。
5. 写入响应未确认且回读仍是原 SKU 时，最终判定拒绝。
6. 回读失败或出现第三个 SKU 时，最终判定人工核对且没有重试。

单元测试通过后，才允许执行一次真实测试。真实测试结束后必须再次只读查询该订单，并报告修改前 SKU、目标 SKU、马帮响应摘要和最终回读 SKU。

## 止损与成功标准

- 最多发起一次真实写入请求。
- 不自动重试，不降级为完整订单表单提交，不操作其余三单。
- 只有回读明确为目标 SKU 才报告成功。
- 任意不确定状态均停止，并要求在马帮人工核对。
- 测试产生的诊断日志不得包含任何认证信息。
