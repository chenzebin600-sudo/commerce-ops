## 1. 当前系统理解

- A2 已提供可追溯的订单、库存、店铺、映射、质量和来源批次事实。
- `growth_source_batches` 保存订单和库存的已应用批次与时间水位。
- `growth_inventory_snapshots` 保存 SKU + 仓库粒度库存、目录、状态和 7/28/42 天来源可见销量。
- `growth_order_headers` 与 `growth_order_lines` 保存去重后的当前订单事实。
- `growth_shops` 与 `growth_shop_source_mappings` 保存店铺身份、负责人和确认范围。
- 产品生命周期通过 `product_sku_lifecycle` 与事件表提供，未确认产品映射时不推断新品。
- 库存标准快照未保存商品中文名称；V2 可从同批次、同行号的脱敏 `growth_inventory_raw_rows.raw_values_json` 只读提取，不修改 A2 事实表。

- 工作树在本节点开始前已有大量并行修改和未跟踪文件。
- V2 实施只追加自身文件，并对共享装配文件做最小范围修改。

## 3. 实施边界

- 不修改 `GrowthRadarService` 的 A2 导入、映射、确认和派生事实逻辑。
- 不修改 COM-015 图片采集业务模块或其迁移。
- V2 使用独立 Repository、Engine、Service 和 API 模块。
- 只在共享 `data-access.mjs`、`server.mjs` 和前端入口做装配。
- 正式 SQLite 不迁移、不写入；所有迁移和计算验证使用隔离临时数据库。
- 已发布分析运行不可覆盖；失败运行不得替换上一成功版本。

## 4. 数据与口径结论

- 指标合同固定为 `GRV2-METRICS-1.0.1`。
- 仅“已发货”订单计入自店实际销量。
- 来源可见销量按唯一仓库求和，不称为公司真实销量。
- 28 天来源销量类目内 P80 定义来源高表现。
- 缺货使用 14/7/0 天阈值；滞销使用 60/90/180 天阈值；新品观察 90 天。
- 国家分析只使用已激活且人工确认的仓库国家配置。
- 当前国家配置为空时仍可发布公司全盘分析；跨源国家和店铺覆盖结果必须为不可用。
