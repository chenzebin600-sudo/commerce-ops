# COM-GROWTH-RADAR-V2 配置与可视化复盘

> 日期：2026-07-25（Asia/Shanghai）
> 指标合同：`GRV2-METRICS-1.0.1`
> 代码基线：`master` / `a8327c524764f89eda8127e32b4aa48e38c3fac6`

## 1. 完成内容

- 新增前端“配置管理”视图，用户可以维护仓库国家映射和确定性规则阈值。
- 配置采用版本化保存；已有分析继续引用原版本，保存后明确提示重新运行分析。
- 国家映射支持确认或排除仓库，并保存国家代码、国家名称及排除原因。
- 规则配置支持来源高表现分位、店铺低占比分位、最小样本、新品窗口、滞销和缺货阈值。
- 新增信号结构环图、库存健康分布、类目来源销量和店铺销售覆盖条形图。
- 图表使用原生 HTML/CSS 和服务端聚合数据，不引入新运行时依赖。

## 2. 后端与 API

新增配置接口：

- `GET /api/growth-radar/v2/configuration`
- `PUT /api/growth-radar/v2/configuration/country-mappings`
- `PUT /api/growth-radar/v2/configuration/rules`

写接口要求 `growth_radar.data.apply` 权限，并记录配置变更审计。服务端负责输入规范化、阈值顺序校验、国家代码校验、版本生成和内容复用。

总览接口新增：

- `supplyBands`
- `categoryPerformance`

这些聚合数据用于可视化，不依赖浏览器对全量 SKU 再计算。

## 3. 隔离数据库验证

仅在系统临时目录的隔离数据库执行：

- 从前端保存 `27` 条仓库配置。
- `25` 条映射到印度尼西亚、泰国、菲律宾、越南或马来西亚。
- `2` 条编码异常仓库按“排除，不参与分析”保存，未猜测国家。
- 从前端保存并激活确定性规则版本。
- 保存后页面显示“新配置尚未进入已发布结果”。
- 点击“更新分析”后，新 published 运行引用新的国家映射和规则版本。
- 国家级 SKU 分析恢复可用；店铺跨源分析仍因确认店铺事实为空而正确降级。

正式 SQLite 未写入配置、规则或分析结果，仍停留在迁移 018。

## 4. 页面验收

桌面端 `1280x720`：

- 三个总览图表均有实际数据、稳定尺寸和可访问名称。
- 配置表、规则表单和版本历史可用。
- 页面无整体横向溢出。

移动端 `430x900`：

- 图表单列展示，环图和条形图没有重叠或空白。
- 规则表单为单列。
- 配置表和历史表限制在页面宽度内，并使用局部横向滚动。
- 页面文档宽度小于视口宽度，没有整体横向溢出。

## 5. 安全边界

- 不使用 AI 评分。
- 不允许前端直接写数据库。
- 不修改指标合同中的有效订单状态。
- 不自动运行经营动作。
- 配置保存与分析发布分离。
- 不修改 COM-015、Listing 或 A2 核心逻辑。
- 不应用迁移 019 到正式数据库。

## 6. 结论

国家映射和规则参数已经从设计文档变成可由用户维护、可版本追溯、可进入确定性分析的正式功能。Growth Radar 的核心结果同时具备表格证据和图表概览，不再依赖纯文字阅读。
