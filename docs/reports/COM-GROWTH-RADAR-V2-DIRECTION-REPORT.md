## 1. 完成内容

Growth Radar 已从通用机会/风险展示调整为面向运营的方向控制台：

```text
国家 × 类目预测日销量排名
+ 自营店铺近 28 天已发货销量
+ 店铺与店长承接
+ 可用库存、在途和覆盖天数
= 明确运营方向
```

新增四类直接行动：悄悄入场、优先发力、补货后发力、守住优势。

## 2. 后端和数据库

- 分析合同升级为 `GRV2-METRICS-1.1.0`。
- 类目排名改用 `source_predicted_daily_sales`，不再用来源可见历史销量替代。
- 新增国家 SKU 和店铺 SKU 方向信号。
- 新增方向汇总读取和 `GET /api/growth-radar/v2/directions`。
- 新增代码迁移 `020_growth_radar_direction_contract.sql`，仅登记新规则合同，不改已有事实表。
- 正式数据库仍停留在 `018_mabang_image_collection_performance.sql`，未应用 `019` 或 `020`。

## 3. 前端

- `方向总览`：国家 × 类目热力图、行动结构、高机会类目和行动队列。
- `SKU 机会池`：预测日销量、类目排名、自营承接、库存、在途和覆盖天数。
- `店铺横比`：店铺销量条形图、店长待办排行、店铺异常表。
- `配置管理`：国家映射和规则参数继续由前端填写并版本化保存到数据库。
- `数据与范围`：继续复用 A2 的店铺确认和数据治理能力。

## 6. 当前风险和启用前条件

1. 正式数据中 107 家店铺仍需要用户确认国家和店长。未确认店铺不会被当作零销量。
2. 正式仓库国家映射必须由用户在配置页面确认，不能使用隔离验收中的名称推断。
3. 来源数据中存在少量乱码类目，需要在导入质量治理中修正，不能由分析层猜测原类目。
4. 正式启用前需要单独批准数据库备份、迁移 `019`、迁移 `020` 和首次正式分析。
5. 当前工作树包含 COM-015 等并行修改，本节点未暂存、提交、删除或回退这些修改。

## 7. 结论

本次优化已经回答运营最关键的三个问题：

1. 哪个国家、哪个类目值得先看。
2. 哪些高预测 SKU 自营没有承接，可以悄悄入场。
3. 哪个店铺或店长存在承接不足、供应受限或优势款需要守住。

当前可以进入人工业务抽样和代码审查，但尚未进入正式数据库迁移或生产启用。
