## 1. 结论

Growth Radar V2.2 的产品方向可以继续，但当前正式数据尚不满足发布“超级店长运营助手”真实结论的条件。

本轮结论为：

| 范围 | 结论 |
| --- | --- |
| 独立 React 前端、线框和模拟数据交互 | 可继续 |
| 正式数据只读预览与数据质量提示 | 可继续 |
| 国家 × 类目机会发布 | 阻断 |
| 店铺 / 店长诊断发布 | 阻断 |
| 当前 7 天 vs 前 7 天趋势 | 阻断 |
| 每位店长最多 10 项正式运营任务 | 阻断 |
| 跨国候选发布 | 阻断 |

阻断来自数据准备度，不是前端实现：

1. 目前只有一段完整的 7 天“已发货”业务窗口，没有前 7 天可比较。
2. 107 家来源店铺均未完成店铺身份、国家和店长归属确认。
3. 最新库存快照的 27 个仓库均未解析到国家。
4. 库存中的预测日销量仍标记为语义未确认，不能直接发布为公司实际销量。
5. 正式库仍止于迁移 018，V2 分析表、任务生命周期表尚未进入正式库。

## 4. 七天趋势缺口

### 4.1 当前可用事实

订单销量口径已经正确过滤为：

```text
order_status = 已发货
```

“已发货”订单共有 1,293 单，业务日期使用 `paid_at`，覆盖：

```text
2026-07-15 至 2026-07-21
```

共 7 个不同日期，且 `paid_at` 无缺失。

### 4.2 阻断原因

设计要求：

```text
当前 7 天销量 vs 前 7 天销量
```

至少需要连续 14 个完整业务日。当前只有一段完整 7 天窗口，因此以下结论都不能发布：

- 店铺销售增长。
- 店铺销售下滑。
- SKU 销售增长。
- SKU 销售下滑。
- 基于趋势的“今日必须关注”任务。

数据不足时必须返回：

```text
insufficient_history
```

不得把缺失的前 7 天当作 0。

### 4.3 日期语义风险

现有订单事实有 `paid_at`，但没有权威 `shipped_at`。当前候选引擎采用：

```text
筛选已发货状态 + 使用 paid_at 作为时间轴
```

该口径可重放、可计算，但“付款日期”不等于“发货日期”。进入正式开发前需要明确冻结以下二选一：

1. 第一版接受“已发货订单的付款日期”作为销量归属日。
2. 后续从来源补充权威发货时间，再切换为发货日期。

未经确认，不应在界面上称为“发货趋势”。

## 5. 店铺与店长身份缺口

107 家来源店铺当前状态：

| 项目 | 结果 |
| --- | ---: |
| 活跃来源店铺 | 107 |
| 身份已确认 | 0 |
| 店长已绑定 | 0 |
| 国家已确认 | 0 |
| 映射状态为 `unmatched` | 107 |
| 身份状态为 `review_required` | 107 |

正式订单头中的 `internal_shop_id` 和 `mapped_country` 均未形成可信映射。

因此当前不能可靠回答：

- 某位店长负责哪些店。
- 某店属于哪个国家。
- 每位店长应收到哪 10 项任务。
- 某店的健康状态是需处理、观察、稳定还是阻塞。
- 店铺之间的可信横向对比。

当前最多只能展示“来源店铺观测”，不能展示“我的店铺”或“店长任务”。

## 6. 国家与类目维度缺口

### 6.1 最新库存快照

最新已应用库存批次：

- 来源行：20,026。
- 快照行：20,022。
- 唯一标准化 SKU：10,327。
- 仓库：27。
- 二级类目缺失：131 行。
- 预测日销量缺失：2 行。
- 可用库存缺失：2 行。

### 6.2 国家映射

20,022 条最新库存快照均为：

```text
mapping_status = country_unresolved
```

正式库尚不存在已生效的仓库国家配置表。因此：

- 国家 × 类目机会热力图不能使用正式数据发布。
- 国家级 Top SKU 不能发布。
- 跨国候选不能发布。
- 国家库存聚合不能发布。

必须先由用户在前端维护并确认仓库 → 国家配置，再写入数据库并带版本运行分析。

### 6.3 多仓预测值

有 3,658 个标准化 SKU 在不同仓库行中出现多个不同预测日销量值。

这不自动代表数据错误，因为不同国家或仓库可能存在不同预测值；但它证明在国家映射完成前不能：

- 跨仓盲目求和。
- 任意选择其中一个值。
- 把多仓值发布为单一“市场预测日销量”。

分析必须先按已确认国家粒度分组，再执行冲突或聚合规则。

## 7. 预测日销量语义缺口

最新库存快照中，预测日销量语义状态为：

| 状态 | 行数 |
| --- | ---: |
| `unconfirmed` | 20,020 |
| `unavailable` | 2 |

V2.2 可以把该字段定位为：

```text
来源预测日销量 / 市场验证参考
```

但不能称为：

```text
公司实际销量
```

在语义确认前，真实机会计算必须：

- 保留来源名称。
- 展示规则版本与证据。
- 对 `unconfirmed` 或 `unavailable` 结果 fail closed。
- 禁止生成高优先级经营任务。

## 8. 产品与在线覆盖缺口

当前：

- `product_identity_mappings`：0。
- `growth_shop_sku_coverage_snapshots`：0。

因此不能从“历史未出单”推断：

- 店铺未上架。
- SKU 未覆盖。
- Listing 不在线。

第一版允许的表达是：

```text
近 28 天未观察到有效销售
```

蓝海动作必须保持：

```text
核查在线状态后低风险测试
```

不得直接输出“优先上架”或“店铺缺少该 Listing”。

## 11. 数据准备优先级

### P0：真实 V2.2 发布前必须完成

1. 前端维护仓库 → 国家配置，并保存带版本的数据库记录。
2. 完成 107 家来源店铺的内部店铺、国家和店长归属确认。
3. 连续采集至少 14 个完整业务日的已发货订单，覆盖目标店铺。
4. 冻结趋势业务日期口径。
5. 确认预测日销量的来源语义及国家粒度。

### P1：任务引擎前必须完成

1. 审批并隔离验证 V2 分析数据模型。
2. 补充当前 7 天、前 7 天及趋势证据字段。
3. 冻结 `growth_focus_items/events` 的任务生命周期合同。
4. 建立产品身份映射或明确 exact-SKU-only 的限制。

### P2：后续增强

1. 补齐 Shopee、TikTok 等平台的正式订单事实。
2. 建立在线 Listing 覆盖事实，替代“未观察到销售”的弱证据。
3. 在足够历史数据后增加稳定趋势和跨周期复核。

## 12. 建议门禁

### 允许继续

- 使用 fixture 的 V2.2 React 页面与交互原型。
- 国家、店铺和店长配置页面的产品设计。
- 数据不足、映射未确认和语义未确认的可视化状态。
- 只读数据质量页面。

### 暂停

- 正式 V2.2 分析运行。
- 真实店长任务生成。
- 正式国家 × 类目机会发布。
- 跨国候选发布。
- 销售增长或下滑任务。
- 任何 migration 或正式库修改。
